国际化 ​

开箱行为一句话：组件里写死的那部分文本是英文，其余全部跟着 locale 走，而 locale 不给就跟着宿主浏览器走。

拆开说是四条：

  • 内建文案（关闭钮的读屏名、分页的翻页说明、上传区的提示、色阶两端的 Less / More 这类）一律英文，换语言经 translations。
  • 日期时间系组件的月份名、星期名、段位先后、周首日与缺省格式串全部由 locale 决定，不写死。
  • locale 的解析链是实例 props → 全局配置 → 宿主的 navigator.language → en-US，calendar / date-picker / date-field / heatmap / time 五个都走它。所以中文浏览器里不配任何东西也是中文日期；服务端渲染期或显式 Scope 没有活动 Window 时读不到宿主语言，落 en-US，不会借用另一个页面的 Window。
  • 例外一处：time-picker / time-field 的小时制不从宿主推。hourCycle 与 locale 都不给时恒是 24 时制，要 12 时制就给其中之一。

服务端渲染的应用应在服务端与客户端显式注入同一个 locale。如果服务端依赖无 DOM 时的 en-US、客户端又依赖 navigator.language，两端可能生成不同的月份、星期与段位顺序，形成水合差异。

周首日跟着 locale 走

一周从周日还是周一起算由 locale 定：en-US 周日起、zh-CN 与多数欧洲语言周一起。 不配 locale 时它跟着读者的浏览器变，同一份代码在两台机器上排出来的月历首列不同。 要固定成一种排法，就把 locale 显式传上去（实例上传，或全局配置里配一次），别依赖缺省。

两个适配器各有一处全局出口，语义一致：Vue 侧是 provideXhConfig（走 provide/inject，可按子树覆盖）， 自定义元素侧是 setXhConfig（模块级，整个文档一份）。

全局注入一次 ​

ts
import { provideXhConfig } from "@xihan-ui/vue";

// 应用根组件的 setup 里
provideXhConfig({
  locale: "zh-CN",
  translations: {
    breadcrumb: { root: "面包屑" },
    pagination: { root: "分页", prevTrigger: "上一页", nextTrigger: "下一页" },
    dialog: { close: "关闭" },
    toast: { close: "关闭" },
  },
});

取值优先级从高到低：实例 props → 全局注入 → 组件内建默认（文案是英文，locale 则再往下问一次宿主浏览器）。translations 按键合并——全局给整包、个别实例只覆盖要改的那一个键即可。

运行时切语言 ​

传 ref 或 getter，切换时用到这些文案的组件跟着重渲：

ts
import { provideXhConfig } from "@xihan-ui/vue";
import { computed, ref } from "vue";
import { enUS, zhCN } from "./locales";

const lang = ref<"zh" | "en">("zh");
provideXhConfig(computed(() => (lang.value === "zh" ? zhCN : enUS)));

语言包就是一个普通对象（XhConfig 类型），按组件名收纳各自的 Translations；每个组件页的 Props 表里列有它的文案键。

locale 收在哪些组件 ​

locale 一律收 BCP 47 语言标记（如 zh-CN、en-US），喂给这几个组件：

组件locale 管什么不给时
calendar / date-picker月份名、星期名、周首日、标题里年月的先后宿主语言，再退 en-US
date-field年月日三段的先后、上午/下午的写法宿主语言，再退 en-US
heatmap月份名、星期名宿主语言，再退 en-US
time用词（zh 开头用中文那套，其余英文）与缺省格式串宿主语言，再退 en-US
time-picker / time-field上午/下午的写法、推断小时制不问宿主：小时制恒 24，上午/下午写 AM/PM

实例上显式给过 locale 的不受全局影响。

作用域与边界 ​

  • 注入走 Vue 的 provide/inject：在应用根 provide 就是全应用默认，也可以只在某个子树 provide 给局部换语言。

  • createToastService / createDialogService 自带宿主应用，接不到组件树里的注入。它们的按钮文案走各自创建时的选项（okText 缺省 OK、cancelText 缺省 Cancel、translations），要让整个服务跟应用同语言就把配置从 config 交进去：

    ts
    const dialog = createDialogService({
  config: { locale: "zh-CN", translations: { dialog: { close: "关闭" } } },
  okText: "确定",
  cancelText: "取消",
});

    config 是一份普通的 XhConfig，服务会在自己那棵子树里 provideXhConfig 一次；不给就走内建默认。

  • 不注入时组件走原路，没有任何额外开销。

  • 自定义元素接不到 Vue 的注入，用它自己那处全局出口，见下。

文档站的示例为什么都在逐实例传

每条示例都是孤立片段，没有应用根可以注入，所以一律写成 :translations="{ … }"。 真实应用按上面全局配一次即可，实例上只留要单独覆盖的那一个键。

自定义元素那一侧 ​

自定义元素拿不到 Vue 的 provide/inject，文案又是对象、只能走 property 不能走 attribute， 所以逐实例设是唯一的老路。setXhConfig 给一处全局出口：

ts
import { setXhConfig } from "@xihan-ui/web-components";
import { defineXhElements } from "@xihan-ui/web-components/define";

defineXhElements();
setXhConfig({
  locale: "zh-CN",
  translations: {
    dialog: { close: "关闭" },
    pagination: { root: "分页", prevTrigger: "上一页", nextTrigger: "下一页" },
  },
});

取值优先级与 Vue 侧一致：元素上的 property → setXhConfig 的全局值 → 组件内建默认（文案是英文，locale 则再往下问一次宿主浏览器）， translations 逐键合并。切语言直接再调一次，已挂载的元素会跟着重渲：

ts
setXhConfig({ locale: "en-US", translations: enUS });

两处差别记一下：

  • setXhConfig 是整份替换，不做深合并——想改一处就把整份拿去改。Vue 侧那份也是同样的语义。
  • 它是模块级的，整个文档一份，没有 Vue 那种「只在某棵子树里换语言」的能力。 真要分区，把那部分渲染成 Vue 组件，或者逐实例设 .translations。
