**`cascader` 的检索档补上键盘规格，并修掉规格照出来的六处缺陷。**

`searchable` 打开后浮层里多一个检索框，焦点落在它身上时按键归它——浮层壳的 `onKeyDown` 头一句就把落在 `input` 里的事件整个让开。这一档此前在 `cascader.keyboard.ts` 里一行都没有，共享一致性套件的键盘覆盖判据（分母正是这张表）因此从来没核过它：表从 14 行涨到 25 行，覆盖从 14/14 变成 25/25。

补规格时按「应该怎样」写，写完发现实现对不上的六处，一并修在连接层，机器面没动：

- **只读时候选选得动。** 列内条目走 `activate()`，头一句就是 `if (!interactive || …) return`；候选走的 `selectSearchResult` 只挡了「整条禁用」，`readOnly` 一路放行——回车或点候选照样改值。现在两条路同一条守卫。
- **高亮会停在整条禁用的候选上。** 上下键按 `Math.min/Math.max` 夹取下标，不认禁用；`searchIndex` 每次改词重置为 0，首条命中恰好禁用时高亮就落在它身上，`aria-activedescendant` 也指过去，而回车什么都不发生。现在高亮恒落在可选候选上，整批都禁用时没有高亮，且这一下的 `Enter` 不再被吞。
- **候选列表不回绕。** 列内导航认 `loop`（缺省开），候选列表却是夹取到头就停。同一台机器上两套走法，现在统一认 `loop`。
- **`Home` / `End` 在候选列表里只移光标。** 候选列表顶着列视图时这两个键该跳首末条可选候选（与 `combobox` 同口径）；检索词为空、列视图还在时仍旧留给光标。
- **`Tab` 收不起浮层。** 浮层壳让开了检索框里的按键，而检索框自己没接 `Tab`，于是 `cascader.kbd.tab` 承诺的「收起且不归还焦点」在这一档不成立。现在检索框自己发 `CLOSE`。
- **检索词为空时上下键什么都不做。** 检索框与列之间没有键盘通路：不打字就只能靠 `Tab` 摸进列里。现在检索词为空时上下键把焦点交给列——有锚点条目就落回它，没有则 `ArrowDown` 进当前列首个可用条目、`ArrowUp` 进末个。

另外把带 `Ctrl` / `Cmd` / `Alt` 的组合从检索框手里放开，与浮层壳同一条家规。

`searchHighlightIndex` 的语义随之收紧：它恒落在一条可选候选上，没有候选或整批禁用时为 `-1`。读它来自己渲候选高亮的调用方不必再另判禁用。公开面的名字、部件、事件与皮肤槽都没动。
