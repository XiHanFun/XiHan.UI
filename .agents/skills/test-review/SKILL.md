# XiHan.UI 测试审查

## 判断标准

每个测试给出“保留、改写、合并或删除”结论，并说明它保护的可观察契约。

- 保留：能在缺陷复发时失败，覆盖公开行为、ARIA、焦点、事件、生命周期、三端一致性或真实视觉结果。
- 改写：只复述实现、mock 后证明 mock、断言内部状态名、依赖脆弱 DOM 顺序或用固定延时碰运气。
- 合并：与相邻用例输入和断言等价，没有提供新的失败定位。
- 删除：不可能失败、只验证常量/快照自身，或已被更高层同等且更清晰地覆盖。

## XiHan.UI 专项

- Headless 单测验证状态、非法输入、键盘、事件和 DOM 投影，不验证真实布局。
- jsdom 不能证明计算样式、Portal 几何、动画完成和浏览器焦点行为；这些应由 Chromium 用例承担。
- 三端一致性测试应比较公开 anatomy、props、事件和键盘，不把三个适配器重复测成三套行为实现。
- 截图基线只有在能人工解释每张变化时才更新；禁止批量接受视觉差异。
- Fake timer 仅在控制时间的用例中启用并还原。

输出按风险排序，附文件和行号。除非用户明确要求运行，否则以静态审查为主；不因缺少新测试自动修改代码。
