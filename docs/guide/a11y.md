# 无障碍与键盘规格

无障碍在 XiHan.UI 里不是「尽量做到」，它是**判据**：每个组件都有一份机读的键盘规格表，它同时是测试的分母。

## 键盘规格表

```ts
export const accordionKeyboard: KeyboardTable = {
  component: "accordion",
  source: "https://www.w3.org/WAI/ARIA/apg/patterns/accordion/#keyboardinteraction",
  rows: [
    {
      id: "accordion.kbd.toggle",
      keys: ["Space", "Enter"],
      when: "focus in trigger, not disabled",
      does: "展开/收起该条目的 content",
    },
    {
      id: "accordion.kbd.next",
      keys: ["ArrowDown", "ArrowRight"],
      when: "focus in trigger, 按键与 orientation 同轴（dir=rtl 时左右键语义互换）",
      does: "焦点移到下一个 trigger，末条不回绕",
    },
    // …
  ],
};
```

每一行有稳定的 `id`、触发按键、生效前置条件、以及效果。全库共 **535 条**，散落在 126 个组件上。

规格表由三方共同消费：

1. **测试**——一致性用例通过 `covers` 字段反查行 id，**缺一行即套件失败**；
2. **文档**——[组件参考](../components/)里每个组件的键盘表就是它渲染出来的；
3. **校验**——`source` 字段指向规格出处（W3C APG 模式、WAI-ARIA、HTML 标准或 WCAG 技术），改行为时能追回依据。

::: tip 分母外化
想让键盘测试通过，只能去写用例，不能去改分母。规格表是先立的契约，不是事后补的记录。
:::

## ARIA 上的几处刻意选择

读组件源码时会反复见到这几种处理，它们都是权衡过的：

**`aria-disabled` 而非 `disabled`**——当禁用项仍需可聚焦时用它。原生 `disabled` 会让元素丢掉焦点，读屏用户就再也 Tab 不到它，也读不到「为什么不能点」。手风琴的禁用条目、加载中的按钮都走这条。

**该不做 roving tabindex 的地方就不做**——手风琴的每个触发器都是独立的 Tab 停靠点，这是 APG 对该模式的规定。组件不输出 `tabindex` 是刻意的，不是遗漏。

**方向键的轴向与书写方向**——垂直列表不响应左右键；RTL 下左右键语义互换。这两件事收在 `navIntentFromKey` 一处，所有列表型组件共享同一份判断。

**不归导航管的按键绝不 `preventDefault`**——否则会吃掉输入法、浏览器快捷键和默认行为。

**输入法组合期不误判**——`isComposingEvent()` 用于识别输入法组合中的按键，避免把候选词确认的 `Enter` 当成提交。

## 背景失活与焦点

模态浮层打开时按固定顺序装配四件事：

1. 注册层，压入层栈；
2. 建消隐层（Esc、点外面、焦点移出）；
3. 建焦点域（陷住 + 回绕 + 归还）；
4. 锁滚动；
5. 推迟一帧给背景加 `inert`。

顺序不能乱，细节见[行为原语](./behavior)。

## 焦点看得见

环由一份公共皮肤画，全库共用：粗细 `--xh-ring-width`、颜色 `--xh-_ring-color`（默认 `--xh-ring-focus`）、偏移 `--xh-ring-offset`。偏移是**负的一个环宽**——环往元素里收，外沿与元素边框外沿重合，聚焦前后占的地方一样大，不会把周围的东西挤开。

WCAG 2.2 的非文本对比（SC 1.4.11）要求焦点指示器对**相邻颜色**至少 3:1。环内收之后，相邻的是两块色：

- **内侧**——元素自己那块面。这是判定基准。
- **外侧**——元素坐在什么上面。它随使用者把组件放在哪儿而变，库这边定不了，所以只量不判。

### 实心面上环取 `currentColor`

面是实心的那几档（实心按钮、选中的开关轨道、选中的日历格、拖拽中的滑块……），环色与面同族，贴上去就看不出来——最坏的档量到 1.00:1，即整条环与底完全同色。这些档在各自皮肤的 `:focus-visible` 规则里把环色槽灌成 `currentColor`，环改取**这块面配对的前景色**。那一支色本来就要在这块面上把字读清楚（实心底与它是 4.5:1），拿来画环自然过 3:1。

::: warning 这不是「环开始随语气」
两条口径要一起看：

- **环不随语气**——`data-tone` 换的是颜色族，环不跟着换。语气色本体当环色够不到 3:1（warning 压白底 2.70:1、success 3.04:1）。没有实心面的那些档一律是 `--xh-ring-focus` 一支色。
- **实心面上取 `currentColor`**——取的是那块面**配对的前景色**，不是语气色。同一块 danger 实心底上，环是这块底上的字色，不是 danger 本体。

判据看的是「环压着的那块面」，不是「组件是什么语气」。皮肤怎么写见[皮肤与样式分层](./styling)。
:::

### 谁在盯着

| 判据 | 查什么 |
| --- | --- |
| `check-focus-ring` | 环的粗细、颜色、偏移写了字面量而不是令牌，主题与全局调整对它无效 |
| `check-focus-ring-surface` | 静态解出每个可聚焦档的面与环色，面压环不到 3:1 却没灌 `currentColor` 的判红 |
| `focus-ring-face-contrast` | 浏览器态：从皮肤推出档位，在真实 Chromium 里逐档量环与面的实测对比 |
| `focus-ring-disabled-ink` | 浏览器态：失效档吃默认环、不取被压过的前景墨；没失效的实心档仍取面自己的前景色 |

`focus-ring-face-contrast` 里躺着一条登记：菜单的触发器在深色下量到 1.97:1，而那块面不是皮肤画的——`menu.css` 写明「触发器的长相归作者」，只画展开档，基础档露出来的是原生 `button` 的 UA `buttonface`。登记两侧反查：挂不出这一档、这一档不再画环、或者它已经过了 3:1，三种情况都判登记过期。

静态与浏览器态两条路各有盲区，所以都留着。静态那条跑得快，交互才出现的状态（`[data-dragging]`、`[data-state='picking']`）照样算得到，但看不见「面画在祖先上」「灌了却被另一条规则把 `color` 换掉」这类；浏览器态那条量的是实测值、看得全，但 `:hover` / `:active` 叠聚焦量不了——真实指针一动就把浏览器切出键盘模态，`:focus-visible` 当场掉——`::before` 铺的底、`@media` 与 `@container` 里的面、连接层内联进 `style` 的面（取色器的色板格、裁剪器的图）也都在门外。

## 浏览器里的自动扫描

一致性套件的 fixture 会被挂进**真实 Chromium**，对初始态与各用例终态跑 axe。终态按形态签名去重，避免同一形态重复扫。

每套 fixture 按根元素的 `data-theme` **明暗各跑一遍**，body 铺 `bg-canvas` / `fg-default` 作底——axe 沿祖先找不到画过底色的元素就按白底算，深色那一遍不铺等于拿深色的字去比白底。

必须在真浏览器里跑：jsdom 没有布局，对比度、目标尺寸、翻面与避让一概演不出来。

```bash
pnpm exec playwright install chromium # 首次
pnpm test:browser
```

## 存量违规登记表

扫出的存量问题登记在 `tooling/testing/src/a11y/known.ts` 里。命中已登记的规则不判失败，但**一条都不再命中时判登记过期**——修好了就必须从表里删掉，不许留着一份早已不成立的豁免。

当前共三条。两个适配器共用的两条：`tag` 的禁用标签文字用的是全库统一的 `fg-disabled` / `bg-muted`（浅色 2.36:1、深色 1.93:1），按 1.4.3 的失效控件豁免不算违规，但 tag 的 root 没有 axe 认得的禁用语义，所以只有它被扫出来；`prompt-input` 的输入框刻意不无条件发 `aria-label`（那会盖掉作者的 `<label for>`），一致性夹具刻意不给文案以钉住这条契约，扫出来就是一个没有名字的 textarea，真实用法里由作者命名。Web Components 适配器自己的一条：`steps` 的必需子节点由作者手写，可能缺角色要求的直接子节点。全局登记为空。登记按主题记账：明暗两遍都要命中的写在共用表里，只在一个主题下成立的放 `knownByTheme`，两侧都有过期反查——登记了却已经扫不出来的一样判失败。

::: warning
这份表是当前状态的诚实记录，不是「已知可接受」。表里还有条目时，请自行评估这两条对你的合规要求是否可接受。
:::

## 步骤重放豁免

只剩一个组件在真机里推不到用例终态，两个适配器共用这条登记：

- `breadcrumb`——扫描必须拦下跨文档跳转，否则测试宿主被导航走；而用例断言的正是「不拦下」，同一文档里不可兼得。
